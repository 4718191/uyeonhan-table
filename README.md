# 우연한 식탁

처음 보는 4~6명이 결이 맞는 사람들과 한 테이블에서 저녁을 먹도록 연결하는 소셜다이닝 서비스의 해커톤 MVP입니다.
신청부터 자동 매칭·재배치·확정, 식당 배정과 단체방 안내, 대화 콘텐츠, 체크인·피드백, 다음 매칭 반영까지
**정상 흐름은 운영자 개입 없이 자동으로** 진행되고, 자동으로 풀리지 않은 예외만 운영자 화면에 올라옵니다.

- **배포 링크:** https://uyeonhan-table-gamma.vercel.app
- **참가자 앱:** 모바일 웹 (`/home`) · **운영자 웹:** `/admin`
- **스택:** Next.js 15 (App Router, TypeScript, Tailwind) · Supabase (Postgres, Auth, RLS) · Vercel (배포, Cron)
- **작성:** 하태훈 (코드 작성은 AI 도구 Claude 활용, 기획 기준 확인·검증·방향 결정은 하태훈)

## 주요 기능

### 참가자 앱 (PRD 17장 참가자 화면 1~10)

- **회원가입·프로필:** 출생연도·성별·MBTI·관심사·나는 어떤 사람·만나고 싶은 사람·식사 가격대, 개인정보·운영 정책 동의
- **신청:** 날짜·지역 복수 선택, 1회권·멤버십(1·3·6개월) 모의 결제, 환불 규정·노쇼 정책 안내, 보유 멤버십·보관한 1회권 사용
- **홈:** 신청·결제·매칭·참석 네 가지 상태와 다음 행동, 자동 매칭 예정 시각, 확정 후 다음 안내 일정
- **매칭 실패 해결 (STA-04~06, PAY-03):** 실패 사유와 추천 일정, 기존 결제 유지 원클릭 이동, 1회권 보관, 원결제수단 모의 자동 환불, 멤버십 기한 1주 연장
- **매칭 확정 상세·단체방 (INF-03~07, CON-01~03):** 식당·주소·지도·가격대·예약명, 함께할 사람(이름·관심사·성향만), 확정 공지·1일 전 리마인드·대화 주제 3개와 아이스브레이킹
- **취소:** 마감 전 취소는 환불, 확정 후 취소는 환불 없음(당일 취소는 이용 제한 대상). 4명 미만이 되면 남은 사람을 같은 회차 다른 테이블로 자동 재배치
- **체크인·피드백·신고 (FDB-01~04, SAF-01):** 체크인, 분위기·대화·식당 평가, 재참여·추천 의향, 사람별 선호(비공개), 신고·차단(비공개)
- **참가 이력·다음 일정 추천 (RET-01·02)**, **앱 내 알림**, **회원 탈퇴**

## 매칭 규칙

- **필수 조건 (완화하지 않음):** 결제 완료, 신청한 날짜·지역, 4~6명, 최고령·최연소 나이 차 8살 이내, 차단·신고·"만나고 싶지 않아요" 관계 분리, 이용 제한자 제외
- **선호 점수 (100점, 운영자 설정 가능):** 나이 25 · 성비 22 · MBTI 18 · 공통 관심사 15 · 만나고 싶은 사람 충족 10 · 새로운 사람 10. 최소 점수(기본 55) 미만 조합은 확정하지 않음
- **재배치 순서 (PRD 7.4):** 같은 날짜 같은 지역 → 같은 날짜 다른 희망 지역 → 신청한 다른 날짜 → 대체 일정 추천(참가자 선택) → 보관·환불(멤버십은 기한 연장)
- **확정 전 재검증 후 자동 확정**, 같은 마감 회차는 한 번만 실행(중복 테이블·환불·단체방 없음)
- **다음 매칭 반영:** 이전에 같은 테이블이었던 사람은 "새로운 사람" 점수 감점, 서로 "또 만나고 싶어요"를 고른 사이는 감점 제외

### PRD와 다르게 정한 것

- **앱 푸시 → 앱 내 알림:** 모바일 웹이라 푸시 대신 앱 안 알림으로 안내합니다.
- **확정 후 1명 취소:** 대기자 자동 충원(STA-07)은 P1이라 제외했습니다. 4명 이상 남으면 유지, 4명 미만이면 재배치합니다.
- **마감·자동 매칭 시각:** 회차마다 직접 정하지 않고 행사 직전 화요일 24:00로 고정했습니다.
- **결제·환불:** 실제 결제 없이 상태 전환으로 모의 구현했습니다(PAY-04 실결제 연동은 P1).
- **운영자 권한:** 운영자 역할은 하나이고, 참가자와 운영자를 분리해 접근을 통제합니다.
- **메시지 문구:** 코드로 관리합니다(운영자 편집은 CON-04, P1).

## 개인정보와 탈퇴 정책 (PRD 16장)

- 다른 참가자에게는 매칭 확정 뒤에도 이름·관심사·성향만 보여 주고, 연락처·출생연도·점수·차단·신고·사람별 선호는 보여 주지 않습니다.
- 운영자만 연락처·출생연도를 볼 수 있고, 운영자 조치(노쇼 확정, 이용 제한, 신고 검토)와 주요 상태 변경은 시간과 변경 주체를 기록합니다.
- **회원 탈퇴:** 진행 중인 신청(결제 대기, 매칭 대기, 실패 해결 선택 전, 참석 예정)이 있으면 탈퇴할 수 없습니다. 탈퇴하면 이름·연락처·직업·식사 조건·매칭 프로필을 바로 지우고 로그인 계정을 삭제합니다. 결제·환불·참가 기록과 상태 이력은 정산·분쟁 대응을 위해 이름 없이 남기고, 다른 사람이 남긴 차단·신고는 그 사람의 안전을 위해 유지합니다. 남은 멤버십과 보관한 1회권은 사라집니다.

## 자동 실행 (Vercel Cron, KST)

| 작업 | 시각 | 내용 |
|---|---|---|
| 자동 매칭 | 화 24:00 | 마감이 지난 회차 매칭·재배치·확정·식당 배정·단체방 |
| 리마인드 | 매일 10:00 | 내일 행사 테이블에 단체방 공지 + 앱 알림 |
| 대화 콘텐츠 | 매일 19:30 (+ 참가자가 단체방을 열 때 보충) | 시작 시각이 지난 오늘 행사 테이블 |
| 행사 종료 | 매일 23:00 | 피드백 요청·다음 일정 추천, 미체크인 노쇼 후보, 피드백 미응답 1회 리마인드 |

모든 작업은 여러 번 실행돼도 결과가 중복되지 않고, 발송이 실패하면 최대 3번 다시 보낸 뒤 반복 실패만 예외 처리함에 올립니다.
**시연 모드**(`DEMO_MODE`, 기본 켜짐)에서는 모임 날짜 전에도 체크인할 수 있습니다. 실제 운영에서는 `DEMO_MODE=0`으로 끕니다.

## 실행과 설정

```bash
npm install
cp .env.example .env.local   # Supabase URL·anon key·service role key, CRON_SECRET, SEED_TEST_PASSWORD
npm run dev                  # http://localhost:3000
```

- **DB:** Supabase SQL Editor에서 `supabase/migrations/0001_init.sql` → `0002_matching.sql` → `0003_messages_once.sql` 순서로 실행
- **시드:** `npm run seed` (가상 참가자 291명, 서울 4개 지역 × 3주 회차, 지역별 가상 식당 3곳, 테스트 계정 4개)
- **시연 초기화:** `npm run demo:reset -- --yes`
- **테스트:** `npx tsx scripts/test/relations.test.ts` (매칭 관계 반영), `npx tsx scripts/test/delivery.test.ts` (발송 재시도)
- **배포:** GitHub `main`에 push하면 Vercel이 자동 배포 (환경 변수는 `.env.local`과 같음, `SEED_TEST_PASSWORD` 제외)
