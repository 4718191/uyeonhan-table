# 우연한 식탁

처음 보는 4~6명이 결이 맞는 사람들과 한 테이블에서 저녁을 먹도록 연결하는 소셜다이닝 서비스의 MVP입니다.
구글 폼 접수, 수기 매칭, 카카오톡 단체방 안내로 돌아가던 운영을 **신청부터 매칭·안내·피드백 반영까지 자동으로** 처리하고,
자동으로 풀리지 않은 예외만 운영자에게 올라오도록 만들었습니다.

- **배포:** https://uyeonhan-table-gamma.vercel.app (참가자 모바일 웹 `/home` · 운영자 웹 `/admin`)
- **기간:** 2026년 10월, 해커톤 과제 (1인 진행, 수료)
- **스택:** Next.js 15 (App Router, TypeScript, Tailwind) · Supabase (Postgres, Auth, RLS) · Vercel (배포, Cron)
- **작업 방식:** 코드 작성은 AI 도구(Claude)를 활용했고, 문제 정의·PRD 해석·운영 정책 결정·검증 설계와 실행은 직접 했습니다.

> 회원가입하면 참가자 흐름을 처음부터 체험할 수 있습니다. 데이터는 가상 참가자 291명으로 채운 시연용입니다.

## 해결하려는 문제

| 기존 운영 (수기) | 우연한 식탁 |
|---|---|
| 구글 폼으로 신청 접수 | 앱에서 프로필·날짜·지역 선택, 모의 결제까지 한 번에 |
| 운영자가 참가자를 직접 매칭 | 마감 시각에 자동 매칭·재배치·확정, 식당 자동 배정 |
| 카카오톡 단체방을 직접 만들고 안내 | 앱 단체방 자동 생성, 확정 공지·전날 리마인드 자동 발송 |
| 식사 후 대화 콘텐츠를 직접 준비 | 테이블 구성원에 맞춘 대화 주제를 모임 시작 시각에 자동 게시 |
| 만족도를 모아 다음 매칭에 수기로 반영 | 피드백·차단·신고가 다음 매칭에 자동 반영 |

## 주요 기능

**참가자 (모바일 웹)**
- 회원가입·매칭 프로필(MBTI, 관심사, 나는 어떤 사람, 만나고 싶은 사람, 가격대), 날짜·지역 복수 선택, 1회권·멤버십 모의 결제
- 홈 한 화면에서 신청·결제·매칭·참석 상태와 다음에 할 일, 다음 안내 시점 확인
- 매칭 실패 시 실패 사유와 추천 일정, 원클릭 일정 이동(기존 결제 유지)·1회권 보관·즉시 모의 환불·멤버십 기한 연장
- 매칭 확정 상세와 단체방(식당·지도·예약명, 확정 공지, 리마인드, 대화 주제), 확정 후 취소
- 체크인, 만족도·재참여 의향, 사람별 선호(비공개), 신고·차단, 참가 이력과 다음 일정 추천, 회원 탈퇴

**운영자 (웹)**
- 운영 대시보드: 회차별 신청·결제·매칭·확정·체크인, 운영자가 볼 일(노쇼 후보, 미처리 신고, 예외)만 강조
- 자동 매칭 모니터, 예외 처리함, 회차·식당 재고 관리, 매칭 가중치·최소 점수 설정
- 신청자·결제·환불(필터, 프로필, 이전 이력, CSV), 테이블·단체방 발송 상태, 안내·리마인드 이력과 재발송
- 참석·취소·노쇼 관리와 이용 제한(경고·4주 제한·영구 제한), 피드백·신고 검토

## 특히 신경 쓴 부분: 이유가 보이는 매칭

자동 매칭은 결과를 믿을 수 있어야 사람이 맡길 수 있다고 생각해, 결과만 내지 않고 **"왜 이 사람들이 한 테이블인지"** 보이도록 만들었습니다.

- 테이블마다 나이·성비·MBTI·공통 관심사·만나고 싶은 사람·새로운 사람 점수와, 어떤 경로로 재배치됐는지가 남습니다.
- 지난 피드백 반영 내역을 실행마다 숫자로 보여 줍니다: 차단·신고·"만나고 싶지 않아요" 관계는 분리, 이미 만난 사이는 감점, **서로 또 만나고 싶어 한 사이는 감점에서 제외**(PRD에 없던 규칙으로 직접 정함).

### 매칭 규칙

- **필수 조건 (완화하지 않음):** 결제 완료, 신청한 날짜·지역, 4~6명, 나이 차 8살 이내, 차단·신고 관계 분리, 이용 제한자 제외
- **선호 점수 (100점, 운영자 설정 가능):** 나이 25 · 성비 22 · MBTI 18 · 공통 관심사 15 · 만나고 싶은 사람 10 · 새로운 사람 10, 최소 점수 미만 조합은 확정하지 않음
- **재배치 순서:** 같은 날짜 같은 지역 → 같은 날짜 다른 희망 지역 → 신청한 다른 날짜 → 대체 일정 추천(참가자 선택) → 보관·환불(멤버십은 기한 연장)
- **확정 전 재검증 후 자동 확정.** 같은 회차는 한 번만 실행돼 테이블·환불·단체방이 중복되지 않습니다.

## 자동으로 돌려도 안전하게

| 작업 | 시각 (KST) | 내용 |
|---|---|---|
| 자동 매칭 | 행사 직전 화 24:00 | 매칭·재배치·확정·식당 배정·단체방 |
| 리마인드 | 매일 10:00 | 내일 행사 테이블 단체방 공지 + 앱 알림 |
| 대화 콘텐츠 | 매일 19:30 (+ 단체방을 열 때 보충) | 시작 시각이 지난 테이블에만 게시 |
| 행사 종료 | 매일 23:00 | 피드백 요청·다음 일정 추천, 미체크인 노쇼 후보, 피드백 미응답 1회 리마인드 |

- 모든 작업은 여러 번 실행돼도 결과가 중복되지 않습니다 (상태 선점, DB 유일 키, 링크 기준 알림 중복 방지).
- 발송이 실패하면 최대 3번 다시 보내고, 반복 실패만 예외 처리함에 올립니다.
- 운영자 조치와 주요 상태 변경은 시간과 변경 주체를 상태 이력에 남깁니다.

## 검증

- **PRD 완료 조건 12개 전체 리허설:** 데이터 초기화 후 신청 → 291명 자동 매칭(테이블 24개) → 재배치·확정 → 단체방·리마인드·대화 주제 → 체크인·피드백·신고 → 다음 매칭 반영(차단한 쌍 분리, 이전 만남 감점)까지 처음부터 끝까지 확인
- **PRD 대조 검증 3회:** 참가자 기능 2회, 운영자 기능 1회. 찾은 차이(피드백 리마인드, 환불 상태 단계, 발송 재시도, 취소 구분 등)를 고침
- **시간이 지나야 일어나는 기능:** 실제 운영은 예약 실행으로 두고, 같은 로직을 운영자 화면의 "지금 실행"으로 시연할 수 있게 함. 시각에 따라 달라지는 동작(시작 전 게시 안 함, 당일 취소, 4명 미만 테이블 해제·재배치)은 검증 스크립트로 시계를 바꿔 실제 코드와 DB로 확인
- **자동 테스트:** 매칭 관계 반영, 발송 재시도

## 운영 정책

| 항목 | 정책 |
|---|---|
| 이용권 | 1회권 9,900원, 멤버십 1·3·6개월(기간 내 무제한 신청, 매칭 실패 1회당 1주 연장) |
| 마감 | 행사(목) 직전 화요일 24:00에 신청·환불 마감과 자동 매칭 |
| 취소 | 마감 전 취소는 환불, 마감 후 취소는 환불 없음, 당일 취소는 이용 제한 횟수에 포함 |
| 확정 후 취소 | 4명 이상 남으면 유지, 4명 미만이면 테이블 해제 후 같은 회차 다른 테이블로 자동 재배치 |
| 노쇼·이용 제한 | 행사 종료까지 체크인하지 않으면 노쇼 후보, 누적 1회 경고 · 2회 4주 제한 · 3회 영구 제한 (시스템 제안, 운영자 확정) |
| 개인정보 | 다른 참가자에게는 이름·관심사·성향만 공개. 탈퇴 시 개인정보 삭제·계정 삭제, 결제·참가 기록은 익명 보관 |

**PRD와 다르게 정한 것:** 앱 푸시 대신 앱 내 알림(모바일 웹), 대기자 자동 충원(P1) 대신 4명 기준 재배치, 실결제 대신 모의 결제, 메시지 문구는 코드로 관리.

## 실행

```bash
npm install
cp .env.example .env.local   # Supabase URL·anon key·service role key, CRON_SECRET, SEED_TEST_PASSWORD
npm run dev                  # http://localhost:3000
```

- **DB:** Supabase SQL Editor에서 `supabase/migrations/0001_init.sql` → `0002_matching.sql` → `0003_messages_once.sql` 순서로 실행
- **시드:** `npm run seed` (가상 참가자 291명, 서울 4개 지역 × 3주 회차, 지역별 가상 식당, 테스트 계정)
- **시연 데이터 초기화:** `npm run demo:reset -- --yes`
- **테스트:** `npx tsx scripts/test/relations.test.ts`, `npx tsx scripts/test/delivery.test.ts`
- **시연 모드:** `DEMO_MODE`(기본 켜짐)에서는 모임 날짜 전에도 체크인할 수 있습니다. 실제 운영은 `DEMO_MODE=0`.

```

lib/                  인증, 상태 표기, 알림·발송 재시도, 이용 제한, 시간(KST)

docs/                 설계 문서
```
